# Architecture

How EdgeStation is put together, for those who work on the app. To set it up, run it and test it, see [Develop](README.md#develop) in the README.

In the app and in this repository, "the Edge" means the display the dashboard is on: a Xeneon Edge, or whichever other display it was given.

- **Edge window**: always open, full screen on the Edge (the first secondary display, unless another monitor is picked in Settings → Display). Shows swipeable pages, each a grid of widgets.
- **Settings window**: opened from the tray icon (left click, or right click → Settings), or by starting EdgeStation again, since only one runs. Created on demand and destroyed on close, so it costs nothing while unused.

Widgets are plain HTML/JS modules loaded at runtime from a folder, like Obsidian plugins. The built-in ones are written in Svelte and compiled to such a module. See [widgets/README.md](widgets/README.md) to write one.

## Repository layout

A pnpm workspace:

| Folder         | Package                    | What                                                                                       |
| -------------- | -------------------------- | ------------------------------------------------------------------------------------------ |
| `apps/desktop` | `@edgestation/desktop`     | The Tauri app (Rust): windows, tray, widget file server, system, media and audio commands. |
| `apps/ui`      | `@edgestation/ui`          | The SvelteKit UI shown in both windows. Tauri loads its static build from `apps/ui/build`. |
| `apps/web`     | `@edgestation/web`         | The website, prerendered by SvelteKit for GitHub Pages (`.github/workflows/pages.yml`).    |
| `packages/sdk` | `@edgestation/sdk`         | The widget SDK, published on npm for widget authors. The built-in widgets use it too.      |
| `widgets/*`    | `@edgestation/widget-<id>` | The built-in widgets, written in Svelte and bundled with the app.                          |

The root scripts (see [Develop](README.md#develop)) forward to the right package. To run one package's own script, filter on it, e.g. `pnpm --filter @edgestation/ui dev` for the UI alone in a browser.

## Platforms

Windows and Linux (X11) build from the same crate. Each module that calls the system has the same layout:

- `mod.rs` holds what the platforms share: the commands, the types, the logic and its tests.
- `windows.rs` and `linux.rs` hold the code of one platform each, with the same functions. A larger side is a folder, `windows/` or `linux/`, with a `mod.rs`.
- `mod.rs` picks the side of the platform once, as `native`, and the shared code calls `native::` functions:

```rust
#[cfg_attr(windows, path = "windows.rs")]
#[cfg_attr(target_os = "linux", path = "linux.rs")]
mod native;
```

Shared code has no `#[cfg]` of a platform. When one platform needs a step that the other doesn't, both sides have the function and one of them does nothing, for example `app_windows::place_again_on_map`. `os/` holds the system code that several modules share: COM on Windows (`os/windows/com.rs`), X11 and D-Bus on Linux (`os/linux/`). `process/` gives the executable of a process and the name that people know it by, for `system` and `audio`.

`desktop-check.yml` lints and tests both platforms on each pull request that changes `apps/desktop`, and fails on a platform `#[cfg]` outside the selectors. The only others are in `lib.rs`, which stops the build on other platforms, and in `os/mod.rs`. A macOS side adds a third file next to each pair and a line to each selector; the build names each module that still lacks one.

| Area                           | Windows                                                 | Linux                                                                                                                                                                                       |
| ------------------------------ | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Window system                  | Win32, WebView2                                         | GTK on X11, WebKitGTK. Under Wayland, GTK prefers XWayland (`os/linux/mod.rs`): child web views, global shortcuts and window positions need X11.                                            |
| Apps (`apps/`)                 | The Apps folder of the shell                            | Desktop entries through GIO, icons from the icon theme                                                                                                                                      |
| Audio (`audio/`)               | Core Audio. `windows/watch/` holds the change callbacks | The PulseAudio API, also served by PipeWire. A subscription sends `audio:changed`, and peak-detect streams feed the meters. `sampler.rs` and the `changed` function of `mod.rs` are shared. |
| Media (`media/`)               | The media sessions of Windows, and their change events  | MPRIS players over D-Bus, and their `PropertiesChanged` and `NameOwnerChanged` signals. `art.rs` and `progress.rs` are shared.                                                              |
| System (`system/`, `process/`) | Process list, network profiles, executable descriptions | `/proc` through sysinfo, NetworkManager over D-Bus. Only interfaces of a device count for traffic. A program takes the name of its app menu entry.                                          |
| Full screen, focus             | Win event hooks, foreground window                      | `_NET_ACTIVE_WINDOW`, `_NET_WM_STATE`, and a pager request to give the focus back                                                                                                           |
| Web views (`widgets/webview/`) | WebView2 events, regions, DevTools user agent           | WebKit signals and snapshots. Tauri packs a child view below the page, so `linux/layer.rs` moves it into an X child window of the Edge, which the X Shape extension cuts.                   |
| Monitors (`monitors/`)         | The display device names                                | The model and the RandR connector, so two monitors of one model differ                                                                                                                      |
| Tray                           | Click opens Settings                                    | App indicators give no clicks, so the menu or a second launch opens Settings                                                                                                                |
